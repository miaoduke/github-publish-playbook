# 07_发布后运营与GitHub配置 / 07. Post-Release Ops & GitHub Config

> **English:** After you flip Public, a few settings and habits keep the repo healthy. This playbook is designed to grow — append every new gremlin you meet.

> **中文：** 转公开后，一些设置与习惯能让仓库保持健康。本经验库是为"生长"设计的——遇到新坑就追加。

---

## 1. Branch protection / 分支保护
- Single-person repos: optional. 单人仓库可选。
- If enabling: Settings → Branches → Add rule → require PR reviews. 若开启则要求 PR 评审。
- For solo repos you may keep it off for a faster workflow. 单人可关闭以提速。

---

## 2. Actions permissions / Actions 权限
- Keep **Workflow permissions = Read repository contents** (default) unless a workflow needs write. 保持默认只读。
- Ensure the token used to push workflows has `workflow` scope. 推送 workflow 的 token 需有 `workflow` 范围。

---

## 3. Each project gets its OWN repo / 每个项目独立成仓
- **Do not jumble multiple projects into one repo.** 不要把多个项目塞进一个仓库。
- Experience: `jiaolong15k-optimization` and `acer-aspire-a615-51g-optimization` are separate repos — each has its own LICENSE/THIRDPARTY/CHANGELOG/audience. 经验：两个项目各自独立成仓，各自拥有许可/合规/受众。

---

## 4. Releases & tags / 发布与标签
- Create an initial `v0.1.0` tag (Releases → Create a new release) so changelog/tarballs are pinned. 建一个初始 tag，固定版本与归档。

---

## 5. Sponsor / 打赏运营
- If using `.github/FUNDING.yml`: commit commented (no button) or with real channels (button shows). 全注释=无按钮；填真实渠道=出现 Sponsor 按钮。
- If using QR images in README: keep them in `assets/` and referenced. 用 README 二维码则放 `assets/` 并引用。

---

## 6. Keep the playbook growing / 让经验库持续生长
When you discover a **new gotcha or a better method**, do:
1. Append to the relevant SOP (or add a new one).
2. Update the master checklist `SOP/00_总清单_发布自检.md`.
3. Commit with a conventional message, e.g. `docs(playbook): add lesson about <X>`.

Keeping a single source of truth that you actually re-read before each release is worth more than the docs staying pristine. 每次发布前真正重读的单一事实源，比保持"文档不改"有价值得多。
