# 06_建仓推送与安全扫描 / 06. Repo Creation, Push & Security Scanning

> **English:** Create the repo **Private** first, push, enable GitHub security features, verify the push, then flip Public only after a final self-check.

> **中文：** 先建 **Private** 仓库、推送、开启 GitHub 安全特性、验证推送成功，最后在最终自检通过后才转 **Public**。

---

## 1. gh CLI login & scope / gh CLI 登录与权限
```powershell
& "C:\Program Files\GitHub CLI\gh.exe" --version
& "C:\Program Files\GitHub CLI\gh.exe" api user --jq .login   # expect your owner name
```
Ensure the token has at least `repo` scope. Configure git to use gh auth:
```powershell
gh auth setup-git
gh auth refresh -s workflow   # for Actions workflows push
```

---

## 2. Create the repo (Private) / 建仓（Private）
```powershell
# Create empty repo defaulting to Private, do NOT add any init files (you already have README/LICENSE)
& gh repo create <name> --private --source . --remote origin
```
**Do not let GitHub add README/LICENSE/.gitignore** — you bring your own. 不要勾选任何初始化文件，自带已有文件。

> Naming: **ASCII only**, no spaces; use a descriptive English slug (e.g. `jiaolong15k-optimization`, `acer-aspire-a615-51g-optimization`). 命名用 ASCII，不用空格，用描述性英文短横线。

---

## 3. Push / 推送
```powershell
git.exe -C "<repo>" add . ; git.exe -C "<repo>" commit -m "..." ; git.exe -C "<repo>" push -u origin main
```

### ⚠️ Verify the push really happened / 验证推送真的成功
PowerShell sometimes **misclassifies git progress output on stderr as `NativeCommandError`**. Don't trust exit 0 alone; verify remotely:
```powershell
D:\PortableGit\bin\git.exe -C "<repo>" ls-remote origin main   # should list the ref
# or
gh api "repos/<owner>/<repo>/commits/main" --jq .sha
```

---

## 4. Enable security & analysis / 开启安全与分析特性
Best via API / gh; web UI equivalents in Settings. 建议 API/gh 方式，网页端等价。

### 4.1 Secret Scanning + Push Protection
```powershell
gh api -X PATCH repos/<owner>/<repo> -f security_and_analysis='{
  "secret_scanning":{"status":"enabled"},
  "secret_scanning_push_protection":{"status":"enabled"}
}'
```

### 4.2 Dependabot security updates
```powershell
gh api -X PATCH repos/<owner>/<repo> -f security_and_analysis='{
  "dependabot_security_updates":{"status":"enabled"}
}'
```

### 4.3 CodeQL code scanning
Enable via Actions workflow. A minimal CodeQL build matrix (cs / python suggests) can be added for Python/Shell/C#. See a `codeql.yml` example in SOP/07 or GitHub's default template:
```powershell
gh api repos/<owner>/<repo>/actions/workflows/...   # after pushing a .github/workflows/codeql.yml
```

---

## 5. Final local self-check before Public / 转 Public 前的最终本机自检
- Re-run `git grep` sensitive scan across the whole tree.
- Confirm no `_private` tracked (`git ls-files | Select-String _private` → empty).
- Confirm gitleaks (if installed) `no leaks found`.
- Confirm file counts in README match `git ls-files`.

---

## 6. Flip Public / 转公开
```powershell
gh repo edit <owner>/<repo> --visibility public
# or web: Settings → General → Danger Zone → Change repository visibility
```
> ⚠️ **Do this only after** final self-check. Public is sticky and your history is now shared. 仅当最终自检通过后再转。公开会扩散历史。
