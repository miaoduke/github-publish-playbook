# 01_脱敏与保密 / 01. Redaction & Secrecy

> **English:** Before anything goes public, every personally-identifiable or machine-specific value must be replaced with a placeholder. This document lists the full inventory of what must be redacted, the placeholder naming convention, and how to scan for leftovers.

> **中文：** 任何内容公开之前，所有可识别用户/具体机器的字段都必须替换为占位符。本文档列出需脱敏的完整清单、占位符命名约定，以及如何扫描残留。

## 1. Placeholder Convention / 占位符约定

Use a single consistent placeholder style so a reader can `grep` for what's missing and replace it. 使用统一风格的占位符，方便读者搜索缺漏并替换。

| Real value 真实值 | Placeholder 占位符 | Examples 示例 |
|---|---|---|
| Linux / Windows username 用户名 | `<USER>` | `/home/<USER>`、`/media/<USER>`、`C:\Users\<USER>` |
| Hostname 主机名 | `<HOSTNAME>` | `<HOSTNAME>-Aspire` |
| Windows C:/data partition UUID 分区 UUID | `<WIN_C_UUID>` / `<DATA_PART_UUID>` | fstab / mount examples |
| MQTT password salt 口令盐值 | `<REDACTED_PWD_SALT>` | MQTT credentials |
| AES key 密钥 | `<REDACTED_AES_KEY>` | decryption keys |
| Plaintext password 明文口令 | `<REDACTED_PASSWORD>` | sudo / accounts |
| Any credential-looking value | `<REDACTED_CRED>` | tokens, secrets |

> **Rule:** When you invent a new placeholder, add a row to the README's "About Redaction" table so it's discoverable. 每新增一种占位符，就在 README 的「关于脱敏」表格登记一条。

## 2. What MUST be redacted / 必须脱敏的清单

- [ ] Real usernames 真实用户名（Linux/Windows）
- [ ] Real hostnames 真实主机名

- [ ] Real personal data paths 个人数据真实路径

## 3. Secrets NEVER to publish / 永不公开的秘密

| Item 项目 | Why 原因 |
|---|---|
| OEM vendor binaries 厂商二进制 | Copyright 版权 |
| Decompiled artifacts 反编译产物 | Derivative copy, copyright risk 衍生复制风险 |
| Credential-extraction scripts 取凭据脚本 | Cracking procedure 破解工序 |
| Raw packet captures 原始抓包 | Cracking + privacy 破解与隐私 |
| Secondary decryption keys 次级解密密钥 | Keep usable local feature private 保密 |
| Personal battery report / OEM registry snapshot 电池报告 / 注册表快照 | Privacy 隐私 |

> **Key principle:** Publish **conclusions, register maps, protocol specs, methodologies + self-authored code**. Keep the **cracking/forensic originals private**. 发布结论/映射/规范/方法论/自写代码；把破解/取证原文留在私有层。

## 4. Scanning for leftovers / 残留扫描

### 4.1 Grep keywords scan
```bash
git grep -nE "<my_username>|<my_hostname>|<my_uuid>|<my_mac>|<my_serial>" -- .
```
Adjust keywords to your actual identifiers. 把关键词换成你的真实标识。

### 4.2 gitleaks (optional, stronger)
```powershell
# Portable install when network available
winget install gitleaks.gitleaks
# then
gitleaks git --path . --verbose
```
If network is unavailable, `git grep` over the leak's common **rules semantics** is an acceptable offline equivalent (see lessons).

### 4.3 Gotcha: purely-numeric passwords
GitHub's default Secret Scanning has **no rule for purely-numeric passwords** (`123456`-style all-digit strings). **Git grep / manual review is mandatory.** 纯数字明文口令不会被 GitHub Secret Scanning 命中，必须主动手动审查 + `git grep`。

## 5. When you find a leftover too late / 如果发现残留太晚

If sensitive data is **already in git history**, and the project is still **private / branch not pushed / not yet public**:
- Prefer **rewriting history with `git filter-repo`** (not `filter-branch`), with a bundle backup of the original first. See [SOP/05](05_本地git初始化与安全提交.md) and the filter-repo lesson.

If already **pushed public**, history rewriting is more complex (all clones must re-branch). Consider GitHub's Secret Scanning alerts + rotating/revoking the leaked secret rather than only redacting text. 已公开推送时，优先按 GitHub Secret Scanning 告警处理并轮换密钥。
