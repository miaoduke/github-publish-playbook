## 3. Disclaimer must-haves / 免责声明必备要素
- **非官方**: no affiliation with vendor / OS maker / manufacturer.
- **风险自负**: reads/writes real system registers; wrong value can destabilize/damage. Use at your own risk.
- **分层**: repo ships conclusions/method/code only; no OEM binaries/credentials/personal data.
- **脱敏**: all device-identifying info redacted.
- **纠错台账**: retracted conclusions kept & annotated, never deleted.

## 4. Windows / Linux capability table / 双系统能力对比表
Align by *feature*, mark feasibility per OS, all **real-machine tested**. 按「功能」对齐，标记各系统可行性，全部实测。

| 功能 | Windows | Linux | 说明 |
|---|---|---|---|
| CPU undervolt | ⛔ | ⛔ | 固件锁死 |
| GPU undervolt | ✅ manual | ⚠️ limited | … |
| SMU 功耗墙 | ✅ | ✅ | … |
| 风扇曲线 | ✅ | ✅ | Win 走 MQTT；Linux 直写 EC |
| … | | | each row a feature |

> **Lesson:** the table immediately answered “等下，Linux 到底能不能调这个” → put it near the top of README, it has very high value. 表格立刻回答「Linux 到底能不能调这个」，价值很高，放在 README 较靠前位置。

## 5. Known Issues as a checkable task list / 已知问题写成可勾选任务
Use GitHub native checkboxes + status icons so progress/impact is visible. 用原生 checkbox + 状态图标让进展/影响可见。

```
状态图标：🟥 待修 · 🟨 待观察/第三方 · 🟩 已解决但有影响
- [ ] **XXX**（说明）— 🟥 待修（范围：…）
- [x] **YYY** — 🟩 已解决（2026-..-..）
- [x] 已关闭项标注在仓库层面关闭或注明
```

## 6. Donation QR displayed directly / 打赏二维码直接展示
- Put QR images in `assets/` and reference them with `![名称](assets/donate_*.jpg)`.
- **Why directly displayed:** per project preference, the QR codes are shown directly in README without adding compliance-risk scare text — a conscious decision made in the Jiaolong 15K release. 二维码直接展示，不额外加合规风险警示文案（这是蛟龙15K 发布的明确取舍）。

## 7. Keep docs in sync with code corrections / 文档随代码修改同步
- Corrections (e.g. deprecated register `0x44F → 0x44C`, power `45W → 35W`) must be **written back to all** README/docs, not just code. 代码纠错要回写所有文档，不只改代码。
- Cross-check file counts claimed in README against `git ls-files` (a count drift bug: README said 214, actually 212). README 声称的文件数与 `git ls-files` 对齐。
