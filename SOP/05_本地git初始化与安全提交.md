# 05_本地git初始化与安全提交 / 05. Local Git Init & Safe First Commit

> **English:** The first commit is where secrets leak. This phase covers git init, signature, **safe add (never -A)**, per-file `check-ignore` verification, and — when needed — history rewriting with `git filter-repo`.

> **中文：** 首次提交正是泄密高发段。本阶段涵盖：git init、署名、**安全 add（绝不 -A）**、逐文件 `check-ignore` 校验，以及必要时用 `git filter-repo` 重写历史。

## 1. Portable git / 便携版 git
Use a portable, controlled git binary to avoid environment surprises. 使用便携版、可控的 git 二进制，避免环境意外。
```powershell
D:\PortableGit\bin\git.exe --version
```

## 2. init on main + signature / 初始化：main 分支 + 署名
```powershell
git.exe init                # default branch main
git.exe config user.name  "Jiaolong15K Optimization Contributors"   # repo-level, neutral during init
git.exe config user.email  "contributors@example.com"
```
Later switch to the **real author signature** for LICENSE/README (see lessons: neutral init-name → real signature at publish). 初始可用中性署名，发布时改为真实署名（LICENSE/README/git 三处一致）。

## 3. ⚠️ Safe add: never `-A` / 安全 add：绝不 `-A`
```powershell
# add public directories one by one
git.exe add 00_结论_已确证 01_协议_逆向成果 02_代码_Windows 03_代码_Linux 04_过程_文档归档
git.exe add LICENSE README.md THIRDPARTY.md CHANGELOG.md CONTRIBUTING.md
git.exe add .github SECURITY?  # whatever exists
git.exe add assets
```
Then check staged set: `git.exe status` and `git.exe diff --cached`. **严禁 `git add -A`，会带回无关/私有文件。**

## 4. Per-file `git check-ignore` verification / 逐文件 check-ignore 校验
Run this **every time** after adding/merging, and always before first commit. 每次 add/合并后、尤其首次提交前都必须执行。
```powershell
$notIgnored = @()
Get-ChildItem "_private_不上传" -Recurse -File | ForEach-Object {
  if (-not (D:\PortableGit\bin\git.exe -C "D:\<repo>" check-ignore -q $_.FullName)) {
    $notIgnored += $_.FullName
  }
}
if ($notIgnored.Count -eq 0) { "OK: all private files ignored ($count)" } else { $notIgnored }
```

> **PS5.1 BOM gotcha:** a `.ps1` wrapper (e.g. `00_git_init_safety.ps1`) may fail to parse under PowerShell 5.1 because **UTF-8-without-BOM is parsed as GBK**. **Use the file-by-file `check-ignore` as the offline equivalent** — don't rely on the script that won't run.

## 5. grep-based secret scan / 基于 grep 的保密扫描
When gitleaks can't be installed offline, do an **equivalent** scan using gitleaks-common rule semantics:
```powershell
git.exe grep -nE "BEGIN (RSA|EC|OPENSSH) PRIVATE KEY|AKIA[0-9A-Z]{16}|ghp_[0-9A-Za-z]{36}|sk-[0-9A-Za-z]{24}" -- .
git.exe grep -nE "<real_username>|<real_hostname>|<uuid>|<password>" -- .
```
Record: real private keys / tokens → 0 hits; placeholder-only hits OK. 记录：真实私钥/Token 0 命中；占位符命中属正常。

## 7. When history rewrite is unavoidable / 必须重写历史时
⚠️ **Only if** sensitive data is already committed and the branch is not yet public/forks-able.

### 7.1 Backup the original history first 先备份原始历史
```powershell
git.exe bundle create "<path>\_backup_pre_rewrite_<date>.bundle" --all
```

### 7.2 Use `git filter-repo`, NOT `filter-branch`
`git filter-repo` handles path/commit rewrites correctly (GitHub disabled `filter-branch`). Install: `pip install git-filter-repo` (Python 3.10).

```bash
# Remove a path from ALL history
git filter-repo --path <private_path> --invert-paths
# Replace a literal in blobs across history
git filter-repo --replace-text <(cat > replace.txt <<'EOF'
<REAL_SENSITIVE_STRING>==>RESERVED
<REAL_UUID>==>RESERVED
C:\Users\<real_username>==>RESERVED
EOF
)
```

### 7.3 Verify + force-push
- After rewrite: `git grep`/`git log -p` for leftovers → 0.
- `git gc` / orphan cleanup.
- Force-push to remote. All commit hashes change. 所有提交 hash 都会变。
- Update any clones / collaborators.

> **Lesson:** history rewrite is the **last resort** — do file-by-file redaction + check-ignore correctly the first time to avoid it. See lessons.
