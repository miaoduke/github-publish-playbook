## 🔥 Anti-Patterns that caused real incidents / 曾真实引发事故的反模式

| # | Anti-pattern 反模式 | What happened 后果 | Fix 对策 |
|---|---|---|---|
| 1 | **`git add -A`** 全仓添加 | 可能带回无关/私有文件 | 按目录逐个 `git add <公开目录>`，`status` 人工核对 |
| 2 | **弱口令明文提交** | 协议文档里出现明文弱口令字符串（含字母+数字组合）被提交 | 脱敏为占位符 + grep 扫明文口令模式 |
| 3 | **纯数字口令逃过自动扫描** | GitHub Secret Scanning 无纯数字密码规则，如 6 位纯数字口令会漏检 | 手动审查 + `git grep` 纯数字口令 |
| 4 | **目录名与内容时间错位** | `..._20260829` 目录内容其实停留在 `08-20`，名字更新实际更旧 | 逐文件比对内容，**不按名字/时间戳判断新旧**（合并前） |
| 5 | **按名字取舍主版本** | 若按名字取 20260829 作主版本，会丢 2 份文档、倒灌 3 个已修 bug | 逐文件名校验「零丢失」；禁止反向合并旧版 |
| 6 | **迁移漏文件** | 根目录散落文件（如 `PowerSettingsExplorer.exe`）首迁漏掉 | 末轮校验逐文件核对新旧 |
| 7 | **README 文件数漂移** | README 声称 214，实为 212（与 `git ls-files` 不符） | 文档数字与 `git ls-files` 对齐并复验 |
| 8 | **只改归档不改运行副本** | 双副本架构下改一不部署，运行程序无变化 | `deploy.sh` 差异化部署 + `diff -rq` 验证 |
| 9 | **`import` 只验语法不做实例化** | UI 类 import 成功却启动崩溃（GTK4 API 误写进 GTK3 项目） | 页面必须『实例化』才算验证通过 |
| 10 | **测试方法本身错误** | 单实例用 `timeout` 启动，进程终止致锁陈旧被正确忽略，误判为"拦截失效" | 让进程真正持续运行再测 |

## 🐛 Gotchas in the tooling (reproducible, fixed now) / 工具链坑（已定位）

### G1. PowerShell 5.1 把无 BOM 的 UTF-8 当 GBK 解析
`00_git_init_safety.ps1`（UTF-8 无 BOM）在 PS5.1 下语法报错。**等价替代**：逐文件 `git check-ignore` 验证 `_private` 全忽略。这是最可靠的离线校验法。

### G2. PowerShell 把 git 的 stderr 进度误报为 `NativeCommandError`
git push 的进度输出走 stderr，PowerShell 可能报错. **别只看 exit 0**；用 `git ls-remote origin main`（或 API 查 commit sha）确认远端真的更新。

### G3. gitleaks 离线不可装 → 用 `git grep` 等价扫描
网络受限时，用 gitleaks 常见规则语义做等价扫描（`BEGIN PRIVATE KEY` / `AKIA…` / `ghp_…` / 真实标识）。验收：真实私钥/Token 0 命中；占位符命中属正常。网络可用时可安装 gitleaks 8.30.x 做最终 secret 扫描。

### G4. GitHub Secret Scanning 不覆盖纯数字密码
同反模式 3。主动人工审查 + `git grep` 扫纯数字口令；必要时旋转/吊销。

### G5. 改远程分支后所有 commit hash 会变
用 `git filter-repo` 重写历史后，所有 commit hash 改变，需 force-push，所有 clone 需重新 based on 新 root/branch。

### G6. `gh auth setup-git` 需要 `workflow` scope 才能推 workflows
推包含 Actions workflow 的仓库时，token 需含 `workflow` scope；执行 `gh auth refresh -s workflow`。

## 🛠️ Sanity principles that prevented worse accidents / 保住底线的原则

1. **单变量**：一次只动一个参数；写三拍（记录原值→写→回读→不一致立即回滚）。
2. **温度红线**：满载 >92°C 停止，>95°C 无条件冷却。
3. **测试前基线 → 测后恢复 → 核对**：所有写操作都这样做。
4. **纠错台账**：被推翻的旧结论保留并标注，不删除。
5. **风险自负**：真实读写系统寄存器，错误配置可致不稳定/损坏硬件。
